# Диагностика зависания Extension Development Host

Зависание второго окна (Extension Development Host) при отладке — это не редкость. Причина часто кроется в том, что вы подозреваете: хост загружает ваши повседневные расширения, и какое-то из них конфликтует или «съедает» ресурсы. К счастью, это решается несколькими способами.

Вот пошаговый план, от простого к сложному, чтобы найти и устранить причину.

## 🔍 Шаг 1: Диагностика — найдите виновника

Прежде чем что-то менять, нужно понять, какой именно процесс зависает.

1.  **Откройте Process Explorer**: В основном окне VS Code вызовите командную палитру (`Ctrl+Shift+P`) и выполните **`Help: Open Process Explorer`** (или `Developer: Open Process Explorer`). Откроется окно со списком всех процессов VS Code и их потреблением CPU и памяти в реальном времени.
2.  **Воспроизведите зависание**: Запустите отладку (`F5`).
3.  **Смотрите на процессы**: Когда второе окно зависнет, посмотрите в Process Explorer. Найдите процесс с высоким потреблением CPU или памяти. Нас интересуют:
    *   **Extension Host**: Именно он выполняет ваш код и код всех расширений.
    *   **Window (Renderer)**: Отвечает за отрисовку интерфейса. Его высокая активность может указывать на проблемы с UI-расширениями.
    *   **Shared Process**: Выполняет общие задачи, например, слежение за файлами.

Если **Extension Host** потребляет много ресурсов, проблема почти наверняка в расширениях.

## 🛡️ Шаг 2: Изоляция — «чистая» отладка

Это самый эффективный способ. Вы запускаете Extension Host без ваших личных расширений, и он не влияет на вашу основную установку VS Code.

### Вариант А (рекомендуемый): Использовать `--profile-temp`

Этот подход создает временный, чистый профиль для отладки, который автоматически удаляется после завершения сессии.

Просто добавьте аргумент `--profile-temp` в вашу конфигурацию запуска в `.vscode/launch.json`:

```json
{
    "name": "Run Extension (Clean)",
    "type": "extensionHost",
    "request": "launch",
    "args": [
        "--profile-temp",
        "--extensionDevelopmentPath=${workspaceFolder}",
        "${workspaceFolder}/sampleWorkspace"
    ],
    "outFiles": ["${workspaceFolder}/dist/**/*.js"],
    "preLaunchTask": "npm: watch"
}
```

Этот способ гарантирует, что ваши повседневные расширения не будут загружены в окне отладки.

### Вариант Б: Отключить все расширения флагом

Можно просто добавить `--disable-extensions` в `args`. Это отключит все расширения в окне отладки.

```json
"args": [
    "--extensionDevelopmentPath=${workspaceFolder}",
    "--disable-extensions"
]
```

**Важно**: Не отключайте расширения через UI в самом окне Extension Host, так как это может изменить ваши глобальные настройки и повлиять на основное окно VS Code.

## ⚙️ Шаг 3: Дальнейшая оптимизация

Если изоляция помогла, но вы хотите найти конкретное проблемное расширение:

*   **Extension Bisect**: Встройте в VS Code инструмент для бинарного поиска проблемного расширения. Запустите `Help: Start Extension Bisect` в командной палитре. VS Code будет по очереди отключать половину расширений и спрашивать, исчезла ли проблема. Это самый быстрый способ найти виновника среди десятков расширений.
*   **Исключите большие папки**: Если Shared Process показывает высокую нагрузку, добавьте в настройках `files.watcherExclude` и `search.exclude` папки вроде `node_modules`, `dist`, `build`. Это снизит нагрузку на слежение за файлами.

## 💡 Дополнительные советы

*   **Проверьте логи**: Если отладка все еще нестабильна, посмотрите логи. Выполните `Developer: Open Extension Logs Folder` в основном окне. Файлы в этой папке могут содержать ошибки, связанные с запуском Extension Host.
*   **Известная проблема с IP-адресами**: В некоторых версиях VS Code была проблема с несовпадением IP-версий при подключении отладчика. Убедитесь, что у вас установлена последняя стабильная версия VS Code.

Начните с **Варианта А (--profile-temp)**. Это должно создать стабильную среду для отладки. Если проблема сохранится даже в изолированном окружении, значит, дело не в конфликте расширений, и стоит проверить код самого расширения или настройки самого VS Code.
