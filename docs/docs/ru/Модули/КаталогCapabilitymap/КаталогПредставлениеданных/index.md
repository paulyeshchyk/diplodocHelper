### Представления данных {#predstavleniya-dannykh}

JSON → Markdown. Универсальные конвертеры, у которых **схема данных отделена от формата вывода**: одна структура JSON — несколько визуализаций.

**Что решает.**

Одна и та же структура данных (например, «список известных проблем» или «реестр модулей») может быть представлена по-разному: сводной таблицей, таблицей с группировкой по колонке, диаграммой-деревом. Если эту логику держать в каждом модуле отдельно — дублирование. `json-to-md` — «одна схема, четыре представления».

**Ключевая идея.**

Схема (`schemas/<name>.schema.js`) описывает поля JSON и их роли (`required`, `multi`, `isDetails`, `label`). Генератор — стратегия (`extended`, `simple`, `grouped`, `treemap`). Новая структура JSON → новый `*.schema.js` → тот же `runGeneration` без правок. Новый формат вывода → новый `lib/generators/*.js` → одна ветка в диспетчере.

**Что НЕ входит.**

`roadmap` (8.2-032) — тоже «из JSON в Markdown», но со строгой специализацией: Gantt, иерархия `группа → модуль → функция`, PlantUML. У него своя capability — **удалено**. `helpMap`, `contexts`, `helptags` — тоже читают JSON или YAML, но их задача — **навигация**, не представление; см. [Навигация](../КаталогНавигация/index.md) и [Отчёты](../КаталогОтчёты/index.md).

**Куда растёт.**

Пока каталог — 1 модуль. По мере появления `json-to-yaml`, `json-to-list`, `json-to-mermaid` — попадают сюда. Критерий: вход — плоский JSON-массив объектов, выход — самостоятельный Markdown-артефакт. Всё, что имеет собственную бизнес-логику (Gantt, секции, индексы) — остаётся в своих capability.
