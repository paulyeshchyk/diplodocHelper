## Правила ведения

1. **Один модуль — одна строка.** Вспомогательные файлы (шаблоны, клиентские скрипты), не выделенные в отдельный модуль, отдельными строками не идут.
2. **Модуль на два слоя** (например, roadmap: генератор + patcher) — **одна строка**, в поле «Слой» через `/`: `pre-processing / post-processing`. ID — один.
3. **Модуль + клиентский скрипт** (например, abbrs: генератор + `abbrs.client.js`) — **две строки**: они живут в разных группах (3 и 5), публикуются и описываются раздельно.
4. **Удалённые модули** — статус `deprecated`, ID остаётся. Поле «Слой» → `—`. Ссылка на статью в архиве — в столбце «Модуль» отдельной строкой, если статья тоже переехала в архив.
5. **Переименование** — меняется только «Модуль» и «Папка», ID тот же.
6. **Смена группы/типа** — ID **не меняется**, даже если первые символы перестали соответствовать смыслу. Идентификатор — паспорт, а не адрес.

## Зарезервированные диапазоны `XXX`

| Диапазон      | Назначение                                                 |
| ------------- | ---------------------------------------------------------- |
| `000` – `099` | Внутренние/служебные идентификаторы (в т.ч. `conventions`) |
| `100` – `899` | Модули                                                     |
| `900` – `999` | Архив, эксперименты                                        |

## Шаблон новой строки

```markdown
| `<XXX>` | <идентификатор> | `src/plugins/<папка>/` | <слой> | active |
```
