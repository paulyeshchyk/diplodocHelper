# Feature Map Editor — Спецификация UI (VS Code Extension)

Редактор размерностей, осей и фильтров для модуля Feature Map.  
Реализуется как **Webview Panel** внутри VS Code Extension.

## Общий вид окна

```
┌───────────────────────────────────────────────────────────────┐
│ Feature Map Editor                                      [×]   │
├────────────┬──────────┬──────────┬──────────┬─────────────────┤
│ Dimensions │ Axes &   │ Filters  │ Preview  │ Settings        │
│            │ Roles    │          │          │                 │
├────────────┴──────────┴──────────┴──────────┴─────────────────┤
│                                                               │
│                     (содержимое вкладки)                      │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

{% list tabs %}

- Вкладка 1: Dimensions

  Управление размерностями и их значениями.

  **Элементы экрана**

  - Кнопка `[ + Добавить размерность ]`
  - Список размерностей (accordion / cards)
  - Для каждой размерности:
    - Имя (slug)
    - Title (человекочитаемое)
    - Field в модуле (`dimToFieldMap`)
    - Таблица значений
    - Кнопки: изменить, удалить, изменить порядок

  **Таблица значений размерности**

  |#  | slug        | title         | dir      | Действия   |
  |---|-------------|---------------|----------|------------|
  | 1 | `ci`        | CI            | `A/CI`   | [✎] [🗑]   |
  | 2 | `techwriter`| Techwriter    | `A/TW`   | [✎] [🗑]   |

  - Кнопка `[ + Добавить значение ]` под таблицей
  - Drag-and-drop для изменения порядка значений и размерностей
  - Валидация:
    - slug уникален внутри размерности
    - field не конфликтует с другими размерностями
    - нельзя удалить размерность, которая назначена как row/column (с подтверждением)

- Вкладка 2: Axes & Roles

  Назначение ролей размерностей (оси тензора + strip-фильтры).

  **Элементы экрана**

  ```
  Row dimension (строки):     [ family          ▼ ]
  Column dimension (столбцы): [ layer           ▼ ]

  Strip dimensions (фильтры сверху):
    ☑ actor
    ☑ capability
    ☐ family          ← недоступна (занята под row)
    ☐ layer           ← недоступна (занята под column)

  Порядок strips:  [actor] [capability]   ← drag-and-drop
  ```

  **Правила**

  - При выборе row/column размерность автоматически исключается из доступных strip'ов
  - Можно менять порядок strip-размерностей перетаскиванием
  - Мини-схема результата:
    > Сетка: **family × layer** + 2 фильтра сверху (actor, capability)

- Вкладка 3: Filters

  Настройка поведения фильтров и пустых значений.

  **Поведение пустых значений (`__empty__`)**

  |#  | Размерность | Включать `__empty__` | Label пустого значения |
  |---|-------------|----------------------|------------------------|
  | 1 | actor       | ☑                    | Без АРМ                |
  | 2 | capability  | ☐                    | —                      |
  | 3 | family      | ☑                    | Без семейства          |
  | 4 | layer       | ☐                    | —                      |

  **Дополнительные опции**

  - ☐ Скрывать размерности, у которых нет ни одного модуля
  - ☐ Показывать счётчики на чипах фильтров
  - (будущее) Сохранённые пресеты фильтров

- Вкладка 4: Preview

  Упрощённый предпросмотр получившейся структуры Feature Map.

  **Пример отображения**

  ```
  ┌─ Actor ──────────────────────────────────────────────┐
  │ [CI 12] [Techwriter 5] ...                           │
  └──────────────────────────────────────────────────────┘

  ┌─ Capability ─────────────────────────────────────────┐
  │ [Cap1 8] [Cap2 4] ...                                │
  └──────────────────────────────────────────────────────┘

            │  CLI          │  UI
  ──────────┼───────────────┼────────────
  FamA      │  alpha beta   │  ...
  FamB      │  ...          │  gamma
  ```

  **Что показывается**

  - Выбранные оси (row × column)
  - Активные strip-фильтры
  - Количество модулей в ячейках (если доступен catalog)
  - Предупреждения (пустые оси, конфликты, отсутствующие field и т.д.)

- Вкладка 5: Settings

  Общие настройки генератора Feature Map.

  **Поля**

  |#  | Параметр              | Пример значения                 | Описание                              |
  |---|-----------------------|---------------------------------|---------------------------------------|
  | 1 | Title                 | Feature Map                     | Заголовок страницы                    |
  | 2 | Section type          | Page                            | `sectionType` в frontmatter           |
  | 3 | Chip label field      | ident                           | Поле модуля для текста чипа           |
  | 4 | Empty cell symbol     | ·                               | Символ пустой ячейки                  |
  | 5 | Counter text          | Показано: —                     | Плейсхолдер счётчика                  |
  | 6 | Reset button text     | Сбросить все                    | Текст кнопки сброса                   |
  | 7 | Module href anchor    | naznachenie                     | Якорь в ссылке на модуль              |
  | 8 | Output path template  | {lang}/Модули/FM/feature-map.md | Шаблон пути генерации                 |

## Архитектура реализации (VS Code)

|#  | Слой              | Рекомендация                                                                 |
|---|-------------------|------------------------------------------------------------------------------|
| 1 | UI                | Webview Panel + React / Vue / Svelte (или чистый HTML+JS)                    |
| 2 | Состояние         | Единый JSON-конфиг (`feature-map.config.json` + `layout.json`)               |
| 3 | Сохранение        | Кнопка «Save» → запись в `_registry/feature-map.config.json` и `layout.json` |
| 4 | Валидация         | В реальном времени в Webview + при сохранении                                |
| 5 | Команды           | `Feature Map: Open Editor`, `Feature Map: Generate`                          |

## Поток работы пользователя

1. Пользователь вызывает команду → открывается Webview.
2. Extension читает текущий `feature-map.config.json` + `layout.json` (+ опционально catalog).
3. Webview получает данные через `webview.postMessage`.
4. Пользователь редактирует вкладки → нажимает **Save**.
5. Extension записывает файлы.
6. (Опционально) сразу запускается перегенерация `feature-map.md`.

## Ключевые правила защиты

- Нельзя удалить размерность, назначенную как `rowDimension` или `columnDimension`, без явного подтверждения.
- `dimToFieldMap` должен оставаться консистентным.
- `__empty__` обрабатывается отдельно (вкладка Filters).
- Все изменения должны быть обратимы до нажатия Save (или иметь явную кнопку Reset).
